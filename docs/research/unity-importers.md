# Unity importers: what exists, and what godot-gulp does

godot-gulp's Unity reader (`godot_gulp/unity.py`) was written after reading the code of the tools below. No code
was copied from them; the coordinate and material formulas were cross-checked against UnityGLTF and unidot (both
MIT). What godot-gulp adds: headless (no Unity, no Godot editor), glTF out, Standard + URP + HDRP materials read
from the .mat YAML with metallic/smoothness and HDRP mask maps repacked into an ORM map, tiling and offset baked into
the UVs, nested prefab overrides applied, mirroring placements baked with their winding fixed, and every result
imported by Godot in the conformance suite.

# Unity asset -> Godot / glTF converters: code survey (2026-10-11)

Cloned shallow, read only, nothing executed. Clones in the same directory as this file.
Licences read from the LICENSE files in the clones (not from GitHub metadata).

## Per tool

### V-Sekai/unidot_importer (MIT, Copyright Lyuma and contributors)
- .unitypackage: package_file.gd ~L190-250. Gzip decompress (`decompress(..., COMPRESSION_GZIP)`), then tarfile.gd walks entries named `<guid>/asset`, `<guid>/asset.meta`, `<guid>/pathname`, `<guid>/preview.png`. A 32-char guid dir is required (`len(guid) != 32` entries dropped). `pathname` is read, first line only (`split("\n")[0]`; some packages have a trailing `\n00`), extension lowercased, illegal paths dropped. Result: `guid_to_pkgasset[guid]` with `.pathname`, `.guid`. A GUID -> path DB lives in asset_database.gd; refs resolve by guid first, then fileID inside that asset.
- YAML: custom line parser, not PyYAML (yaml_parser.gd). Document separator `--- !u!<classID> &<fileID>` is split on spaces (`parts[1].substr(3)` = class id, `parts[2].substr(1)` = fileID); `stripped` suffix sets `is_stripped`. `%YAML`/`%TAG` lines skipped. Flow maps `{x: 1, y: 2, z: 3}` are classified by their keys: x,y -> Vector2; x,y,z -> Vector3; x,y,z,w -> Quaternion; r,g,b,a -> Color; fileID/guid/type -> a ref `[null, fileID, guid, type]`. Numbers < 24 chars are parsed to int/float unless the key is in STRING_KEYS (m_Name, value, propertyPath, typelessdata, etc.). Handles multi-line single/double-quoted scalars by tracking missing closing quotes. Also has a binary YAML-equivalent path. `parse_dependency_guids` just scans for `guid:` text, used to order imports.
- Hierarchy: GameObject (class 1) -> components list; Transform (4) keys m_LocalPosition / m_LocalRotation / m_LocalScale / m_Father / m_Children; asset_meta.gd keeps `transform_fileid_to_parent_fileid`, `fileid_to_gameobject_fileid`, etc.
- Nested prefabs: PrefabInstance (class 1001) with `m_SourcePrefab`, `m_Modification.m_Modifications[]` of `{target: {fileID, guid}, propertyPath, value, objectReference}` (object_adapter.gd ~L4281-4420; `m_Name` mod renames, others applied through `convert_properties`). Child object ids inside an instance are derived as `(prefab_fileID ^ fileID) & 0x7fffffffffffffff` (asset_meta.gd `xor_or_stripped`, citing the Unity forum + gamedolphin/bevity prefabs.rs), with `prefab_source_id_pair_to_stripped_id` consulted first for stripped docs. Prefab variants become inherited .tscn (they hack a stub scene file because GDScript cannot create inherited scenes).
- Coordinates (verified): position `Vector3(-x, y, z)`; quaternion handled as `(x,-y,-z,w)` (object_adapter.gd ~L5013-5034: `rot_quat.y = -y; rot_quat.z = -z`); scale unchanged; mesh vertices and normals `* Vector3(-1,1,1)` (object_adapter.gd L611); AABB centre and collider centres `* (-1,1,1)`; UVs V-flipped in `formatted_vector2_subarray(..., true)`. Triangle indices are NOT reversed because Godot front faces are clockwise (glTF is CCW, so for glTF you must reverse). Scale sign handling: Godot only supports +1/-1 sign combos per axis, so they restore signs and add 180 degree rotations (L4930+).
- Materials: object_adapter.gd L808-960, `UnidotMaterial.create_godot_resource`. Standard shader only (README: "Material (standard shader only)"). m_SavedProperties.m_TexEnvs / m_Floats / m_Colors, plus `m_ShaderKeywords` / `m_ValidKeywords` to know which features are on. albedo = `_Color` * `_MainTex` (fallbacks `_Tex,_Albedo,_Diffuse,_BaseColor,_BaseColorMap`, then any non-"Map" slot); `uv1_scale` / `uv1_offset` from that slot's m_Scale / m_Offset (no V correction visible: probable bug for offset.y). `_BumpMap` + `_BumpScale`. Emission when `_EMISSION`: `_EmissionColor` HDR split into colour/mag, energy = max component. `_OcclusionMap` green channel, strength `_OcclusionStrength`. `_MetallicGlossMap`: metallic from R; if `_GlossMapScale` != 0 it bakes a `.roughness.png` with `A' = 1 - _GlossMapScale * A` (L1000-1030) and reads roughness from alpha; else `roughness = 1 - _Glossiness` (L929). `_ALPHATEST_ON` -> alpha scissor with `_Cutoff`; `_ALPHABLEND_ON` / `_ALPHAPREMULTIPLY_ON` -> alpha blend (premultiply not done). `_DOUBLESIDED_ON` -> cull disabled. No URP `_BaseMap/_Smoothness/_SmoothnessTextureChannel` logic (only as albedo name fallbacks) and the HDRP `_MaskMap` is only a commented stub (L3416). Detail maps not done.
- Meshes: FBX goes through Godot's built-in ufbx when present (asset_meta.gd `is_using_builtin_ufbx`), else FBX2glTF (package_import_dialog.gd `check_fbx2gltf`). They binary-patch `UnitScaleFactor` in the FBX before conversion (asset_adapter.gd L1149-1230) to realise `.meta` `meshes.useFileScale` and `meshes.globalScale`: `desired = fbx_unit_scale * globalScale` if useFileScale else `100 * globalScale`. .asset Mesh (class 43) decoded from `m_VertexData` typeless blob: channel table, strides, formats (float32/16, unorm/snorm 8/16), submeshes with firstByte/indexCount/baseVertex/topology (quads split, L560-640). `.meta` model importer keys used: materials.materialImportMode/importMaterials/materialLocation, externalObjects (L6641), internalIDToNameTable (maps fileIDs of sub-meshes to names). Not seen anywhere: `bakeAxisConversion`.
- Breaks / weak (README "Known issues", plus grep): memory hungry (preparses everything, 10-12 GB), animation imports on main thread, FBX2glTF bugs (ngons lose triangles, RotationPivots), missing-GUID refs not reported clearly, humanoid retargeting limits. 62 FIXME/TODO in object_adapter.gd, 18 in asset_adapter.gd. Everything is tied to a running Godot editor (no CLI), so unusable headless as is.

### barcoderdev/unitypackage_godot (MIT, 2023)
- Delegates unpackaging and YAML-to-dict to the external `unitypackage_util` (separate repo, not read). Godot side (lib/unitypackage/) maps docs by type: Transform, MeshFilter, Prefab, PrefabInstance only; anything else logs `UnsupportedType`.
- Coordinates (_base_common.gd): position `(-x, y, z)`, quaternion `(-x, y, z, -w)` (same rotation as `(x,-y,-z,w)`, negated), scale unchanged. Confirms the same X-mirror convention.
- Materials (asset.gd L395+): only `_MainTex`, `_MetallicGlossMap` (as metallic texture only, "TODO: Test if this is correct"), `_EmissionMap`, `_Color`; `_BumpMap`, `_OcclusionMap`, `_ParallaxMap` all `pass`. Weak. Useful only as a second confirmation of the X flip.

### KhronosGroup/UnityGLTF (MIT, Copyright 2017 AltspaceVR; v2.22.1)
- Not an importer of Unity files: it runs in Unity and exports live objects, so it never sees YAML, GUIDs or prefab overrides. Its value is the authoritative Unity -> glTF maths.
- Coordinates (Runtime/Plugins/GLTFSerialization/Schema/SchemaExtensions.cs): `CoordinateSpaceConversionScale = (-1, 1, 1)`; `TangentSpaceConversionScale = (-1,1,1,-1)`; position/normal = unity * scale; quaternion axis = `-1 * (x,y,z) * (-1,1,1)` = `(x,-y,-z)`, w unchanged; matrices `S * M * S` with S = diag(-1,1,1,1). Triangles: `FlipTriangleFaces` swaps indices 0 and 2 of every triangle (ExporterMeshes.cs L352). UVs: `FlipTexCoordArrayVAndCopy` (v = 1 - v). Cameras/lights get an extra node with `InvertDirection = Quaternion(0,-1,0,0)` because glTF cameras look down -Z.
- Materials (Runtime/Scripts/SceneExporter/ExporterMaterials.cs): alpha `_Cutoff` -> MASK; `_BumpScale` -> normalTexture.scale (L648); occlusion from `_OcclusionMap` or `_MaskMap`; smoothness from `_Smoothness` or `_Glossiness` (L766); `if _MetallicGlossMap && _METALLICGLOSSMAP keyword -> smoothness = _GlossMapScale` (L775); `roughnessFactor = 1 - smoothness` (L788) or, with a map, factor 1 and roughness baked into the texture (`smoothnessRangeMax = 1 - roughnessMultiplier`); when a metal-gloss map is present metallicFactor = 1 (L846). Texture repack shader Runtime/Resources/MetalGlossOcclusionChannelSwap.shader L72-76: output `R = occRangeMin + col.g*(occRangeMax-occRangeMin)`, `G = 1 - (smRangeMin + col.a*(smRangeMax-smRangeMin))`, `B = metRangeMin + col.r*(metRangeMax-metRangeMin)`. That is glTF ORM from a Unity metal(R)/gloss(A) map with occlusion in G, which is exactly the HDRP `_MaskMap` layout (R metallic, G AO, B detail mask, A smoothness). HDRP remaps come from `_MetallicRemapMin/Max`, `_SmoothnessRemapMin/Max`, `_AORemapMin/Max` (L859-865), baked into the texture and factors set to 1. Tiling/offset -> `KHR_texture_transform` with `offset = (ox, 1 - oy - sy)`, `scale = (sx, sy)`, rotation; falls back to the main texture's transform (`_MainTex_ST`, `_BaseMap_ST`...) (L520-605). Export covers `_BaseMap/_BaseColor` (URP) and `_BaseColorMap` (HDRP) names.
- Weak: needs Unity to run (can't be called from our CLI); `_GlossMapScale` handling is a known Unity-vs-glTF ambiguity; no support for detail maps or parallax.

### AssetRipper/AssetRipper (GPL-3.0)
- Direction is built player -> Unity project. Input: bundles, serialized files, not .unitypackage (RoadMap.md L71 lists "Export as Unitypackage" as future work). AssetRipper.Yaml is an emitter (YAMLWriter, Emitter), not a reader of project YAML.
- GLB path (Source/AssetRipper.Export.Modules.Models): GlbCoordinateConversion.cs has the same `(-1,1,1)` scale, tangent `(-1,1,1,-1)`, quaternion `(x,-y,-z,w)`; GlbSubMeshBuilder.cs L182-184 adds triangles as `(i+2, i+1, i)`, i.e. reverses winding. Materials (GlbLevelBuilder.cs ~L190-260) are weak: only `_MainTex/texture/Texture/_Texture` as base colour (else any other texture) and `_Normal/Normal/normal` as normal; no metallic/roughness/emission/AO, no factors, no tiling. Not a model for material mapping.
- Useful as behaviour reference for how Unity serialized Mesh vertex streams decode (it is the most complete implementation, MIT-incompatible to copy).

### K0lb3/UnityPy (MIT, 2019-2026)
- Binary only (bundles, `.assets`, SerializedFile.py); no YAML, no .unitypackage. export/MeshExporter.py `export_mesh_obj`: vertices `-x`, normals `-x`, faces emitted `(c, b, a)` (reversed), UVs unchanged (OBJ V convention is bottom-left like Unity, so no flip). Gives a clean Python reference for decoding `Mesh` vertex streams (helpers/MeshHelper.py: `MeshHandler.process`, `get_triangles`). Useful only if we ever need to read compiled `.asset` Meshes from binary-serialized packages (text-serialized Mesh `.asset` YAML is more common in .unitypackage and needs the same stream decode on the hex `_typelessdata` blob).

### Unity FBX Exporter (Unity Companion License), Zylann
- FbxExporters: licence restricts use to Unity-dependent projects; it exports to FBX via native SDK; not useful.
- Zylann: README says experimental, 2D proof of concept, runs inside the Unity editor. No licence file.

## Cross-cutting findings

- No existing tool does what we want headless: unitypackage -> glTF with materials repacked, prefab overrides applied, no engine running. Unidot comes closest but is bound to Godot's editor APIs and outputs Godot resources, not glTF. UnityGLTF has the right maths but runs inside Unity.
- Everyone agrees on the conversion: mirror X, plus winding reversal for glTF.
- Everyone doing Unity->Godot leans on external FBX converters (ufbx / FBX2glTF) and does model scale by patching `UnitScaleFactor`.
- Material coverage is poor everywhere except UnityGLTF (Unity-side). URP Lit and HDRP Lit are not read from YAML by any tool.

## Build plan for ours (Python CLI, Apache-2.0)

### Pipeline
1. `.unitypackage`: `tarfile.open(mode="r:gz")`. Group members by first path component `guid`. Read `<guid>/pathname` (first line, strip), `<guid>/asset.meta` (YAML, `guid:` and importer block), `<guid>/asset` (may be absent for folders). Reject `..` and absolute pathnames. Build `guid -> {path, meta, asset_member}`. Folder assets have no `asset`.
2. YAML reader (pure Python, no PyYAML tag hacks): preprocess text by splitting on `^--- !u!(\d+) &(-?\d+)( stripped)?$`, drop `%YAML`/`%TAG` lines, then feed each body to `yaml.CSafeLoader` (`yaml.safe_load` works once the tag header is removed; the flow maps `{fileID: 1, guid: x, type: 3}` parse natively). Keep PyYAML only for the body, not for the multi-doc header. Watch for: ints > 2^63 never occur but fileIDs can be negative; strings like `m_Name: 'it''s'`; `_typelessdata` hex blob (parse as str). Avoid float-parsing of hex strings that look like numbers (`Hash`, guid `0e5...` -> force str by regex for guid keys, as Unidot's STRING_KEYS does). Doc model: `{(class_id, file_id): {"type": root_key, "body": dict, "stripped": bool}}`.
3. Refs: `{fileID, guid, type}`; guid absent -> same file; fileID 0 -> null; type 2 = asset in project, 3 = other file; guid `0000000000000000f000000000000000` = Unity built-in resources, `0000000000000000e000000000000000` = built-in extra (Default-Material etc.): map to a default material / skip.
4. Hierarchy: GameObject(1).m_Component[*].component; Transform(4) keys above; roots are Transforms with m_Father fileID 0 (sort by scene `SceneRoots` m_Roots if order matters). Nested prefab: PrefabInstance(1001) with `m_SourcePrefab`, `m_TransformParent`, `m_Modification.m_Modifications[] {target, propertyPath, value, objectReference}`. Child fileID inside an instance = `(instance_fileID ^ source_fileID) & 0x7FFFFFFFFFFFFFFF` (Unidot asset_meta.gd L455-460; stripped docs listed in the scene give the authoritative mapping and should be preferred). Apply overrides by propertyPath: `m_LocalPosition.x`, `m_LocalRotation.x/y/z/w`, `m_LocalScale.x/y/z`, `m_Name`, `m_IsActive`, `m_Materials.Array.data[N]`. Also `m_RemovedComponents`, `m_AddedGameObjects` in newer Unity.
5. Local TRS to glTF node: translation `(-x, y, z)`; rotation `(x, -y, -z, w)`; scale `(sx, sy, sz)` unchanged (Unity local scale is axis-aligned in the local frame, so a mirror conjugation leaves it unchanged). Equivalent matrix form `S M S` with `S = diag(-1,1,1,1)` (UnityGLTF SchemaExtensions.ToUnityMatrix4x4Convert). Use SciPy-free math: normalise the quaternion.
6. Mesh vertices: position `(-x,y,z)`; normal `(-x,y,z)`; tangent `(-x,y,z,-w)` (UnityGLTF TangentSpaceConversionScale); UV `(u, 1-v)`; indices per triangle `(i0,i1,i2) -> (i2,i1,i0)` (UnityGLTF FlipTriangleFaces / AssetRipper GlbSubMeshBuilder / UnityPy OBJ all do this). Skinning: bind poses convert as matrices `S M S`.
7. FBX inside the package: do not convert coordinates ourselves; convert FBX -> glTF in an engine (ufbx via bindings, or Blender, or FBX2glTF) and treat the result as already glTF (right-handed, +Y up, metres). Then apply the `.meta` scale: with `meshes.useFileScale == 1` the effective factor is `fbx_UnitScaleFactor/100 * globalScale` (cm FBX -> metres); with `useFileScale == 0` it is `globalScale` applied to the raw file units. Check this against ufbx's own unit handling before relying on it (Unidot's formulas at asset_adapter.gd L878-896 are expressed in Godot's pre-scale and differ by that 100x). `bakeAxisConversion` is not handled by Unidot; handle it as a rotation delta later.
8. Materials (Standard / URP Lit / HDRP Lit) to glTF `pbrMetallicRoughness`, all read from `m_SavedProperties.m_TexEnvs / m_Floats / m_Colors` (note m_Colors are in gamma space when `m_ColorSpace`... verify per project; Unity serialises `_Color` as the sRGB value shown in the inspector, glTF baseColorFactor is linear: convert with the sRGB EOTF, as Unidot does with `linear_to_srgb()` for emission):
   - base colour tex: `_MainTex` (Standard), `_BaseMap` (URP), `_BaseColorMap` (HDRP); factor: `_Color` / `_BaseColor`.
   - alpha: `_Mode` 0 opaque, 1 cutout -> `alphaMode MASK`, `alphaCutoff = _Cutoff`; 2 fade / 3 transparent -> BLEND. URP: `_Surface` 0/1, `_AlphaClip` + `_Cutoff`. HDRP: `_SurfaceType`, `_AlphaCutoffEnable`. Or fall back to keywords `_ALPHATEST_ON`, `_ALPHABLEND_ON`, `_ALPHAPREMULTIPLY_ON` (Unidot L932-940).
   - Standard metallic/smooth: when `_MetallicGlossMap` is set, texture R = metallic, A = smoothness; roughness texture G (glTF) = `255 - smoothScale * A`, where `smoothScale = _GlossMapScale` (Standard, if smoothness source is Metallic alpha, `_SmoothnessTextureChannel == 0`) else `_Glossiness`; if `_SmoothnessTextureChannel == 1` the smoothness comes from the albedo alpha. metallic factor 1 when a map is bound, else `_Metallic`. No map: `roughnessFactor = 1 - _Glossiness`, `metallicFactor = _Metallic`. (UnityGLTF ExporterMaterials.cs L766-846; Unidot object_adapter.gd L897-960.)
   - URP Lit: `_MetallicGlossMap` same layout; smoothness property is `_Smoothness`, channel `_SmoothnessTextureChannel` (0 = metallic alpha, 1 = albedo alpha); same formula as above.
   - HDRP Lit: `_MaskMap` R metallic, G AO, B detail mask, A smoothness. Pack ORM: `R = AORemapMin + G*(AORemapMax-AORemapMin)`, `G = 1 - (SmoothnessRemapMin + A*(SmoothnessRemapMax-SmoothnessRemapMin))`, `B = MetallicRemapMin + R*(MetallicRemapMax-MetallicRemapMin)` using `_AORemapMin/Max`, `_SmoothnessRemapMin/Max`, `_MetallicRemapMin/Max` (MetalGlossOcclusionChannelSwap.shader L72-76 and ExporterMaterials.cs L859-865). Set metallicFactor = roughnessFactor = 1. HDRP normal map `_NormalMap`; strength `_NormalScale`.
   - AO: write into the same ORM texture as R when the occlusion map is the same file as the metallic map, otherwise repack (Pillow channel ops). Occlusion strength: `_OcclusionStrength` (Standard) to `occlusionTexture.strength`.
   - normal: `_BumpMap` (Standard/URP `_BumpMap`), strength `_BumpScale`; if the texture import type is "normal map" fine, else DirectX/OpenGL flip: Unity and glTF both use OpenGL (+Y up) tangent-space, no green flip.
   - emission: `_EmissionColor` (HDR, may exceed 1) -> `emissiveFactor = rgb / max(1, maxcomp)` and `KHR_materials_emissive_strength = max(1, maxcomp)`; texture `_EmissionMap`. Only when `_EMISSION` keyword is on (Unidot L862).
   - tiling/offset: from `m_TexEnvs[_MainTex].m_Scale` / `m_Offset`: `KHR_texture_transform { offset: (ox, 1 - oy - sy), scale: (sx, sy) }` (UnityGLTF L600). Per-texture on glTF; if the file carries one transform for all maps, replicate it on each texture. If the pipeline can't carry the extension, bake the transform into UVs per primitive (our own usdmat code in tools/assets already does the same for USD).
   - double sided: `_Cull` 0 or keyword `_DOUBLESIDED_ON`.
9. Output: one glTF per prefab/scene node tree with per-material PNG textures deduped by content hash (we already do this for USD in tools/assets/usdmat.py).

### Where we beat the existing tools
- Headless CLI, no engine required (Unidot needs a running Godot; UnityGLTF needs Unity).
- Reads YAML materials for URP and HDRP, not only Standard.
- glTF output with real ORM repacking and KHR_texture_transform (AssetRipper's GLB writes only base + normal; Unidot writes Godot resources).
- Deterministic, cached, tested via fixtures (we already have the conformance-fixture pattern from USD).
- Structured report of what was dropped (scripts, shaders, unsupported component classes), which Unidot lacks ("does not indicate clearly when assets are missing GUID references").

### What to credit in NOTICE
- Unidot Importer (MIT, Lyuma et al.): stripped/XOR fileID formula, UnitScaleFactor rules, mesh-stream decode if ported.
- UnityGLTF (MIT, AltspaceVR / contributors): coordinate conversion constants, material mapping decisions, texture-transform formula, ORM repack formulas.
- UnityPy (MIT, K0lb3): only if the Mesh vertex-stream decoder is ported.
- Do not copy from AssetRipper (GPL-3.0) or FbxExporters (Unity Companion).

### Risks to test first
1. Mirror X vs. glTF facing: Unity +Z forward is kept; all three tools above keep +Z forward and mirror X. Verify with a package that has an asymmetric prop.
2. `_Color` colour space (gamma vs linear) and `_EmissionColor` HDR range.
3. Mixed scales and negative scale in prefab overrides (Godot cannot represent negative-scale combos; glTF can, but mirrored nodes flip winding: bake those meshes, as our USD step c does).
4. FBX unit handling: compare ufbx result against the Unidot rules before trusting either.
5. `.meta` `externalObjects` material remaps and `internalIDToNameTable` (needed to bind per-submesh materials to imported FBX meshes).
